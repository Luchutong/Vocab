1

创建个人 Token

Token 代表你的账户权限，每台受信任设备建议分别创建，便于单独撤销。

名称只用于帮助你识别设备，不会发送给 Agent。
2

复制 curl 请求

不需要下载仓库、安装依赖或配置 MCP。让 Agent 执行下面的命令即可。

接口地址 {{ api_base_url }}/api/agent/import

给 Agent 的最小命令

curl '{{ api_base_url }}/api/agent/import' \
  -H 'Authorization: Bearer {{ token_example }}' \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: agent-$(date +%s)" \
  --data '{"words":["abandon","dense","elapse"]}'

把 {{ token_example }} 替换为刚生成的 Token，并把 words 数组改成要导入的单词。不要让 Agent 在回复中复述 Token。

请求字段

位置名称要求
HeaderAuthorization必须为 Bearer 个人Token
HeaderIdempotency-Key建议设置。重试时复用同一个值，避免重复记录复习
JSONwords非空字符串数组，单次最多 100 个单词
3

查看返回结果

Agent 可根据 JSON 判断哪些词已导入，哪些词需要你检查拼写。

返回结果示例

{
  "ok": true,
  "imported_count": 3,
  "failed_count": 0,
  "imported": [
    {
      "word": "dense",
      "definition": "密集的；浓厚的",
      "created": true,
      "next_review": "2026-06-17"
    }
  ],
  "failed": []
}

批量中某个单词失败不会回滚其他有效单词。失败项会附带原因和可能的拼写建议。

4

验证配置

先用一个测试单词确认链路，避免一次提交大量内容后才发现配置错误。

  1. 向 Agent 提供上面的 curl 命令，并要求它把 words 改成 ["abandon"] 后执行。
  2. Agent 应返回导入数量、中文释义以及是否为新词。
  3. 刷新本站“今日测验”，该单词应出现在当天待复习列表中。
  4. 再次导入同一单词不会重复创建词条，但会按一次新的导入复习记录处理。

不要要求 Agent 在回复中复述 Token。工具只需要读取环境变量，不需要知道或展示密钥内容。

5

常见问题

按 curl 输出和 HTTP 状态码快速定位。

401：Agent Token 无效或已撤销

检查 Authorization: Bearer ... 中的 Token 是否完整，确认没有多余空格，并在本页确认该 Token 仍处于有效状态。Token 丢失时请撤销旧 Token 并重新创建。

404 或连接失败

确认 curl 中的接口地址是 {{ api_base_url }}/api/agent/import，并确认 Agent 所在环境可以访问本站。

证书验证失败

应为站点配置可信 HTTPS 证书和完整证书链。不要通过关闭 TLS 校验来绕过问题，也不要通过公网 HTTP 发送 Token。

单词没有导入

服务端只接受本地词典能够确认的英文单词。查看返回值中的 failed 和 suggestions，修正拼写后重新提交。

有效 Token

建议每台设备使用独立 Token。撤销操作立即生效，不会删除已经导入的单词。
